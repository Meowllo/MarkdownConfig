# .mc 语法速查（源自 MarkdownConfig SPEC v0.1/v0.2）

## 文件与兼容性



* 后缀 `.mc`，内容为 Markdown 超集：CommonMark 兼容正文 + 少量 HTML 注释标记。

* 现有 `.md` 升级：改名为 `.mc` 并添加标记即可，无需重写。

* 标准 Markdown 渲染器（GitHub 等）可正常渲染：HTML 注释自动隐藏，**值即所见文本**。

## @var 单变量



```
\<!--@var NAME \[type=TYPE]-->VALUE\<!--@/var-->
```



* `NAME`：标识符，支持点号命名空间（`site.title` → 输出嵌套对象）。

* `VALUE`：两标记之间的文本，trim 后取值。

* `TYPE`（可选）：`string | number | int | boolean | json | text`；缺省自动推断。

* `int`：要求整数值，其余规则同 `number`（v0.2 新增）。

* 自动推断按 JSON 语法：`42`→number，`true`→boolean，`[1,2]`→array，`{"a":1}`→object，`"abc"`→string，其余→string。

* **值含换行时必须以&#x20;**`type=json`**&#x20;或&#x20;**`type=text`**&#x20;声明**，否则报错。

示例：



```
连接超时：\<!--@var TIMEOUT\_MS-->3000\<!--@/var-->毫秒
```

渲染显示「连接超时：3000 毫秒」；`mc export` 输出 `{ "TIMEOUT_MS": 3000 }`。

## @table 表格



```
\<!--@table NAME-->

\| 列1 | 列2 |

\| --- | --- |

\| 1   | 2   |

\| 2   | 4   |

\<!--@/table-->
```



* 两个标记都必须**独占一行**（允许首尾空白）。

* 表头 = 键；单元格类型自动推断（同 @var；空单元格 → `null`）。

* 读出为对象数组：`[{ "列1": 1, "列2": 2 }, { "列1": 2, "列2": 4 }]`。

* 列名重复 / 表头与分隔行缺失 / 行单元格数不一致 → 报错。

## 普通注释与围栏



* 无 `@` 前缀的 `<!-- ... -->` 完全忽略，不产生变量。

* 围栏代码块（` ` \`\`\` 或 `~~~`）内的标记被忽略，不作为配置。

## 块 ID（评论锚定与跳转）



* 行尾 `^id`（Obsidian 风格），或 `^id` 独立一行紧跟块后。

* 示例：`# 产品需求 ^p1`、段落后跟一行 `^b12`。

* config 变量 / 表格本身可用 `NAME` 作为锚点。

## 错误规则（fail loud）



| 情况                                      | 行为                                     |
| --------------------------------------- | -------------------------------------- |
| 标记未闭合 / 错配 / 嵌套                         | 报错（含行号）                                |
| 同名变量重复声明                                | 报错（`mc export --allow-override` 时后者覆盖） |
| 点号命名空间与标量冲突（`site.title` 与 `site` 同时存在） | 报错                                     |
| 值含换行但未声明 `type=json/text`               | 报错                                     |
| 表格列重复 / 结构不完整                           | 报错                                     |
| `@var` 出现在表格区域内、表格标记出现在 `@var` 值内       | 报错                                     |
| 声明了不存在的类型                               | `unknown type: xyz`                    |

## canonical 输出



* `mc export` 输出：键名递归排序、2 空格缩进 JSON；同输入永远同输出（字节稳定）。

* 这是跨语言移植（Tier 2）的一致性校验基准。
